# Core interaction contract 0.1.0

Published 1 November 2026 for the bounded offline build. This is the owned core packet. `schemas.json` uses JSON Schema 2020-12; validate envelopes against named `$defs`. `examples.json` contains concrete generic examples. Domain state and arguments remain domain-owned. Distributed under the repository MIT license.

The prototype uses Node.js ES modules and no installed dependencies. The schemas are language-neutral. The kernel uses no game, account, lesson, billing, renderer, model or media service library. The standalone package exposes this kernel through `eirvio/core`.

## Callable local API

`Registry.register({ruleset, rulesVersion, stateSchemaVersion, validateState(state), operations: {[operation]: {validate(arguments), apply(state, arguments, target)}} , project(state, audience)})`. Validators return the boolean `true` on success; all other values reject. Reducers are synchronous, trusted, deterministic and return `{state, result}`; a rule rejection throws `DomainError(code)`. `Registry.registerEffect(kind, validateParameters)` registers a bounded generic effect kind. No external I/O is allowed inside reducers/projectors. Projectors return an object; observations conservatively set `partial: true` because only the domain can certify completeness.

`Runtime.create({runtimeId, runtimeFence, scenes, scopes, views}, registry, store)` initializes one runtime. Scenes have the schema shape (revision initially 0); scopes are IDs, views are optional context bindings. `new Runtime(registry, store)` attaches a local writer to an existing store. All local API calls are synchronous and atomic; no network server is implied.

| Method | Result / meaning |
| --- | --- |
| `observe(sceneId, scopeId, context, viewId?)` | Projected observation and exact guards |
| `submit(command, context)` | Stored terminal command outcome; state changes only here or at an invoke sequence checkpoint |
| `submitSequence(sequence, context)` | Idempotent admission; no step executes until `advance` |
| `advance(sequenceId, context)` | At most one atomic checkpoint; returns sequence status, current index and results |
| `control(envelope, context)` | Idempotent interrupt, closeScope, end, bindView, forkScene, tick or recover |
| `claimEffect(effectId, context)` | Rechecks current scope/runtime/view/scene basis; marks dispatched before returning effect |
| `receiveReceipt(receipt, context)` | Idempotently records one delivery layer; cannot mutate domain state |
| `getOutcome(operationId, context)` | Exact stored terminal/admission result or `OUTCOME_UNKNOWN` |
| `getSequence(sequenceId, context)` | Sequence checkpoint and terminal status |
| `snapshot(context)` / `exportReplay(context)` | Host-private recovery artifacts |
| `replay(bundle, registry)` | Validates versions/integrity and reconstructs state without reducer execution or effect dispatch |
| `MemoryStore.fromReplay(bundle, registry)` | Builds a simulated store that enforces `RECOVERY_REQUIRED` for new work until `recover`; old outcome lookup/retry remains available |

Trusted `context` is supplied by the host, never copied from model/client JSON: `{runtimeId, scenes: ['main'], scopes: ['coach'], operations: ['counter.add'], controls: ['interrupt'], effects: ['toy.show'], observe: true, inspect: true, receipts: true, dispatch: true, admin: false, audience: 'public'}`. Omitted permissions deny. `admin: true` grants all **inside the local process only**, not authentication. A production gateway must create contexts from verified authorization and recheck policy on every call. Sequence advancement requires a fresh context and rechecks each operation. Snapshot/replay exports require admin and are not public observations.

## Normative semantics

Exact protocol version is `0.1.0`. Scene revision increments once for a validated domain transaction. Control revision increments on controls. Scope epochs fence future work and never undo committed state. `closeScope` permanently closes that scope; `end` closes all command admission. A separate authorized scope can continue on the current scene after `closeScope`; no scope-reopen operation exists. Host media/usage shutdown is outside this package.

Each command explicitly names its scene, runtime fence, exact scene revision and scope epoch. Optional `guards.view` binds all of `viewId`, `viewEpoch`, and `interactionRevision`; if any differs, reject `STALE_INTERACTION`. Selection changes use trusted `bindView` with a strictly newer interaction revision, even when scene revision is unchanged. Attention-sensitive commands/effects must supply this binding. The kernel stores generic context numbers, never selection or identity semantics.

Authenticate/authorize access first. An identical command/control/receipt/sequence ID and payload returns its original stored outcome before freshness checks. Same ID with changed payload rejects `DUPLICATE_ID_MISMATCH`. IDs share one runtime operation namespace; use unique prefixes. ID outcomes are retained for the full in-memory store lifetime with no eviction. An unknown ID is not proof of failure. No production retention window is promised.

Interrupt and closeScope require scopeId/scopeEpoch plus exact control revision. End requires exact control revision. Delayed same-ID retries return the first result and do not increment epochs again. A new stale request is rejected. Fork requires sourceSceneId/sourceRevision and a fresh sceneId; it deep copies the exact current source into an isolated demonstration/practice scene, revision 0, with lineage. No merge API exists.

`bindView` requires sceneId and view. New views begin at epoch/revision 0. Updating a view requires interactionRevision to increase; viewEpoch cannot decrease and must increase when changing scenes. `tick` advances a host-supplied logical monotonic clock by bounded ticks, enabling deterministic waits without wall-clock reads. When tick reaches an installed wait's deadline, it atomically terminates that sequence unless a matching receipt was already retained. A receipt arriving afterward cannot win the expired wait; a retained earlier receipt can still be consumed by advance. `recover` requires a new never-used runtime fence, atomically cancels unfinished sequences/effects and advances all scope epochs; committed results remain. Recovery fences prior local writer handles. After losing a recovery acknowledgement, attach a fresh handle and query/retry its operation ID; an old handle never adopts a newer fence merely by retrying an old recovery ID.

Sequences have at most 32 steps, no loops or user code. Invoke/effect steps must name exactly one `expectedRevision` or an earlier successful invoke `revisionFromStep`; the latter binds that actual resulting revision, never whatever state exists later. Finish is last; waits reference earlier effects. Derived command/effect IDs are `encodeURIComponent(sequenceId) + '/' + encodeURIComponent(stepId)` and must fit the 160-character ID limit at admission. System stop IDs have no slash and cannot alias these. Advance revalidates state, scope, view and current grants. Waits first inspect retained receipts, including receipts received before wait installation. Deadlines begin when the wait checkpoint is installed, and explicit tick commits timeout ordering. Terminal statuses never resume; earlier commits remain when later steps fail/cancel/degrade. Completion is execution only, never learning evidence.

Effects are persisted intents outside the state transaction (in this prototype, persistence is in-memory). `claimEffect` is at-most-once handoff. A crash after claim can lose delivery; recovery cancels uncertain output instead of blindly replaying it. Adapters must fence again immediately before actual output using runtime/scope/view and state basis, and retain cancellation markers. Runtime-generated `runtime.stop` effects carry `canceledRuntimeFence`, `canceledScopeId` and `canceledEpoch` in parameters; adapters stop only work matching that runtime fence/scope at or below that epoch. They must not let a delayed stop cancel a newer epoch. Stop intents are dispatchable after scope/runtime closure and do not depend on a current scene revision. A late receipt from an obsolete scope/view/runtime or state basis is rejected. A receipt may describe completed, canceled, failed or unknown delivery; render, reconciliation and playback are independent layers. State commits are never receipt-driven. Terminal layer evidence cannot be overwritten by a contradictory late receipt. Played offsets are adapter observations, not proof of comprehension. The host must reconcile canceled effects on sequence failure/deadline; this prototype has no background dispatcher or remote delivery guarantee.

`MemoryStore` performs compare-and-swap of the entire next state, outcome index, sequence checkpoint and effect intents in one synchronous transaction. It keeps a hash-linked post-state log. Failure hooks `store.failNext = 'before'` and `'after'` simulate before-commit failure and lost acknowledgement after commit. **Durability is simulated; process exit loses memory unless a host saves an export.** Replay pins a final cursor/hash as well as its genesis, so missing tails/gaps fail explicitly. Hashes detect accidental corruption, not hostile re-signing. A real storage port must implement atomic `initialize(state)`, `read()`, `commit(expectedCursor, expectedWriterFence, nextState, event)`, and `exportReplay()` with persistent CAS/fencing and protection of stored integrity roots. Full-state log records are deliberately inefficient for this small prototype.

Limits: 32 sequence steps, 8 scenes, 64 KiB input envelopes, 10,000 replay records, bounded effect parameters, explicit wait timeout ≤10,000 ticks. Retained state/outcome history is not production resource management. Transport, distributed lease management, automatic timers, authorization service, encryption, durable disk storage, lifecycle pause/resume, compound interrupt-and-input and generalized branches are outside 0.1.0. The host can serialize interrupt then learner submit; this is not advertised as an atomic compound API.

Stable rejection codes include INVALID_SCHEMA, UNSUPPORTED_VERSION, FORBIDDEN, UNKNOWN_OPERATION, RULE_VIOLATION, STATE_CONFLICT, SUPERSEDED_SCOPE, SCOPE_CLOSED, STALE_RUNTIME, STALE_INTERACTION, CONTROL_CONFLICT, DUPLICATE_ID_MISMATCH, RESOURCE_LIMIT, SESSION_CLOSED, OUTCOME_UNKNOWN and DEADLINE_EXCEEDED. Schema/authorization failures before admission throw `DomainError`; well-shaped authorized requests rejected by guards/rules return a stored `rejected` outcome. Adapter diagnostics include RECEIPT_CONTEXT_MISMATCH, RECEIPT_CONFLICT, EFFECT_NOT_DISPATCHED and UNKNOWN_EFFECT. Storage/replay exceptions include STALE_WRITER, STORAGE_CONFLICT, STORAGE_UNAVAILABLE, ACKNOWLEDGEMENT_LOST, RECOVERY_REQUIRED and INTEGRITY_ERROR; reconcile uncertain acknowledgement by operation ID. No stale command is silently rebased. Reserved JavaScript prototype names are forbidden as identifiers; `__proto__`, `constructor` and `prototype` keys are also rejected anywhere in JSON input. The identifier restriction is explicit in the wire schema; the key restriction is a stricter prototype JSON intake rule.

Reference: the implementation uses built-in [Node test runner](https://nodejs.org/api/test.html) and [crypto hashing](https://nodejs.org/api/crypto.html), exercised on the installed Node v25.8.1. The JSON dialect is defined by [JSON Schema 2020-12](https://json-schema.org/draft/2020-12).
